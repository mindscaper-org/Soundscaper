처리를 단순화하기 전에 실시간 효과의 비용을 비교합니다.

## 시작하기 전에

실시간 효과와 대표적인 바쁜 구간이 있는 프로젝트를 사용합니다. 측정값은 이 장치와 작업량을 설명하며 플러그인의 보편적인 순위는 아닙니다.

## 단계

1. **도움말 > CPU profiling**을 엽니다.
2. 패널을 연 뒤 재생을 시작하거나 다시 시작해 각 실시간 효과를 측정합니다.
3. 여러 번 갱신되는 동안 확인합니다. 효과 행을 기본 편집기 행과 비교하고, 비용이 높은 효과 하나를 우회한 뒤 같은 구간을 다시 재생합니다.
4. 완료하면 패널을 닫고 유지할 처리를 복원합니다.

## 결과 확인

CPU 사용량이 단일 코어 용량을 초과할 수 있습니다. 100%는 CPU 코어 하나가 완전히 사용 중임을 뜻합니다. CPU 백분율과 경과 처리 시간 백분율을 비교합니다. 대시는 측정값이 없다는 뜻이지 비용이 0이라는 뜻이 아닙니다.

## 제한 및 복구

경과 처리 시간에는 스케줄링 지연이 포함됩니다. GPU 사용량과 외부 보조 프로세스는 제외되며 프로파일링 자체도 오버헤드를 추가합니다. 우회된 효과는 별도로 표시됩니다. 무음 중 적절한 프로세서를 절전시키려면 효과 헤더의 **추가 옵션 > Auto-idle**을 엽니다. 연속된 타이밍이 필요한 효과에서는 끄세요. 관련 설정은 [로컬 처리](/help/local-processing/)를 참조하세요. 변경을 비교할 때는 항상 같은 구간을 다시 재생합니다.
